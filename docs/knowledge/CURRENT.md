# Content Review 当前知识

## 目标

为社区 UGC 提供文字、图片、视频三类独立审核服务，并通过统一网关接入。明确高风险可直接阻断，中风险进入人工复核，低风险放行并保留可追踪结果。

## 当前服务拓扑

```text
业务系统
  -> gateway :8040
       -> text-audit :8010
       -> image-audit :8020 -> text-audit
       -> video-audit :8030 -> image-audit + text-audit
```

- 网关负责统一入口、媒体类型转发和异步结果查询。
- 文字、图片、视频服务分别部署，不能把所有审核逻辑重新耦合进网关。
- `review-admin` 仍属于规划能力，不能描述成已经落地的生产服务。

## 分层审核原则

1. 规则模板处理明确且低成本的风险。
2. 小模型处理辱骂、暴力、广告、诈骗等语义风险。
3. 上下文聚合合并原文、父评论、标题、OCR、ASR 和业务风险信息。
4. 小型 Agent 只处理灰区、隐晦表达和复杂上下文，不应全量同步调用。
5. 人工复核处理中高风险、争议和申诉。
6. 人审与申诉结果回流，用于更新规则、阈值和训练样本。

## 各媒体链路

- 文字：归一化、规则/词库、语义模型和上下文判断。
- 图片：基础校验、NSFW、NudeNet、OCR；OCR 文本回调文字审核。
- 视频：FFmpeg 固定抽帧、场景切换补帧、图片审核、音频提取、faster-whisper ASR、文字审核。

## 公共响应合同

默认简要业务响应字段为：

- `content_id`
- `result`
- `action`
- `risk_level`
- `reason`

`result/action/risk_level` 保留英文机器码；`reason` 默认中文。只有显式 `brief=false` 才返回更完整的分数和证据字段。

## 配置与状态

- `configs/policy.yaml` 保存审核政策和规则配置。
- `configs/thresholds.yaml` 保存模型及风险阈值。
- 网关异步任务状态落在 `storage/moderation-jobs`。
- Docker Compose 定义 8010、8020、8030、8040 端口及服务调用关系。

## 安全边界

- 图谱可以记录数据流和证据位置，但不能收录用户原文、OCR/ASR 内容、图片、视频或证据快照。
- 模型权重和生产审核记录不进入 Git 知识目录。
- 政策版本、阈值和返回语义变化必须作为语义更新记录。

实时分支、HEAD、未提交文件和知识漂移状态由 `kg context` 动态生成。
